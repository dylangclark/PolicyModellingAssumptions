Methodology

RegistryPipelineMethodology

Principle

Preserve evidence before aggregation

The registry stores each observation or assumption with a stable variable definition, source series, geography, reference period, target period where applicable, publication vintage, units and document evidence. Publisher revisions create a new record version rather than silently replacing history.

Record types

Observation
A measured historical or current value, such as CPI, population or a market price.
Forecast
A source’s projected value for a future period.
Policy target
A stated objective or legal requirement; not treated as a forecast.
Scenario or sensitivity
A deliberately varied model input or outcome.
Model parameter
An input such as WACC, ELCC, reserve margin or technology cost.

Uncertainty products

Source scenario range retains low, reference and high cases from one source. Cross-source planning envelope summarizes comparable values from independent source families after standardizing units, geography, target period and dollar basis. Historical predictive interval is calculated from past forecast errors and is the only range normally described with statistical coverage language.

Publication controls

Collection and public release are separate controls. A source can be ingested for internal analysis while its records remain excluded from the public site pending licence review. Before publication, every required source must have a recent successful run and every configured output must pass a reference-period freshness check. Raw source files are stored by content hash on the collection machine and are not automatically committed to GitHub.

Regulatory filings

The next engine registers each filing by hash, extracts page-level evidence into a review queue, and requires approval before values enter the public registry. Automated language-model extraction may propose candidates, but it does not bypass deterministic validation or human review.
